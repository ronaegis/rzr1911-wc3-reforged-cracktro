# RZR D Cracktro 03 — Warcraft III: Reforged

Decompilation and a WebAssembly/WebGPU port of the Razor 1911 demo-division
intro. Original code by **Anat & Dubmood**, graphics by **GOTO80**, and music
by **zabutom**. See [credits and provenance](CREDITS.md).

The browser player uses the recovered shaders, text, fonts, palette, sync
tracks, and XM module. GPU rendering runs through WGSL translations of the
original shaders. WebAssembly supplies frame uniforms and music decoding.

## Build and run

Prerequisites: Node.js 22+, Python 3, Rust, `wasm-pack` 0.13.1, and LLVM Clang
with `wasm-ld` available. On Windows, the build also checks the standard LLVM
installation directory. Set `CLANG` to use a different compiler executable.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --version 0.13.1 --locked
npm ci
npm run build
python -m http.server 8080 --directory web
```

Open **http://127.0.0.1:8080** in a WebGPU-enabled browser (tested in Edge).
WebGPU requires localhost or HTTPS. Click **Start demo** to start music and
visuals together; **Mute** and **Replay** remain available during playback.
The presentation lasts 67 seconds.

Controls and status text hide when playback starts. Move the mouse to reveal them; they hide
again after five seconds of inactivity. A touch or Tab key also reveals them.

Choose Low **512×288**, Mid **1024×576** (default), or High **2048×1152**.
The selected canvas resolution stays fixed while CSS stretches it to fill
the page. Switching resolution does not restart playback.

The original executable is **not needed** to build or run the player. The
extracted assets and translated shaders are included. The music WASM module
is generated by the build and is not checked in.

## Package for hosting

```sh
npm run build
npm run package
python -m http.server 8080 --directory dist
```

`dist/` contains only the static runtime: HTML, JavaScript, WASM, shaders,
and buffers. Host those files on an HTTPS static host, including GitHub Pages.
Asset URLs are relative, so hosting below a repository path is supported.
Serve `.wasm` files as `application/wasm` and `.js` files as JavaScript.

The GitHub Actions workflow builds, runs unit and Rust tests, and uploads a
`static-site` artifact. Successful default-branch builds also deploy `dist/`
to GitHub Pages. Pull requests and other branches only build and test.

### GitHub Pages setup

1. In the GitHub repository, open **Settings → Pages**.
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Push the workflow to the default branch, or run **Build, test and deploy
   Pages** manually from the **Actions** tab with the default branch selected.
4. Wait for both `check` and `deploy` to succeed. The deployment job reports
   the published URL.

For this repository the project site is
https://ronaegis.github.io/rzr1911-wc3-reforged-cracktro/.
No personal access token or SSH secret is needed by the workflow; it uses
GitHub's built-in token. See [GitHub's custom workflow documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Validation

```sh
npm test
cargo test --locked --manifest-path web/engine/Cargo.toml
npm run test:browser
```

Browser tests require a working WebGPU adapter. They use installed Edge on
Windows. On other platforms, run `npx playwright install chromium` first;
`BROWSER_CHANNEL` can select another Playwright channel. GPU tests run
locally rather than relying on hardware in GitHub-hosted runners.

The browser tests check 12 timeline frames, resolution switching, music
synchronization, replay, startup errors, and particle output against the
unmodified recovered shader. Captures go to ignored `out/verification/`.
Run `node tools/profile-browser.mjs` against the local server for GPU timings;
this additionally requires the adapter's `timestamp-query` feature.

## Source layout

| Path | Contents |
|---|---|
| `web/` | Current browser player and shaders |
| `web/native/` | C adaptation of recovered frame/sync routines and key data |
| `web/engine/` | Rust XM playback wrapper using xmrs/xmrsplayer |
| `decompile/c/` | Ghidra pseudocode, function index, and combined export |
| `decompile/hlsl/` | HLSL recovered from original DXBC |
| `decompile/wgsl/` | Baseline shader translations used by the adapter/tests |
| `decompile/shaders/` | Extracted shader reflection reports |
| `decompile/assets/` | Original XM module |
| `analysis/` | Asset extraction and shader preparation scripts |
| `tools/` | Ghidra exporters, shader converter, profiling and native comparison tools |
| `tests/` | Asset, frame, particle and browser checks |

The Ghidra output is reference pseudocode, not compilable original source.
209 of 210 functions decompiled; the large constructor at `0x140001534`
timed out. Its pass sequence and sync data were recovered from disassembly.
The browser port adapts the recovered routines, uses translated shaders, and
uses an alternate XM mixer. It is not a proven pixel- or sample-identical
reimplementation of the complete original executable.

See [rendering and validation notes](web/RENDERING.md) for pass provenance,
compatibility changes, optimization details and comparison limits.

## Regenerating extracted data

Obtain the [original release archive](https://files.scene.org/get/demos/groups/razor_1911/windows/rzr_d_cracktro_03-warcraft3_reforged.zip),
unpack its UPX executable, and place the result at
`original/unpacked/cracktro.unpacked.exe`. Original release files remain
ignored by Git.

```sh
python analysis/extract_web_buffers.py
cargo build --release --locked --manifest-path tools/spv2wgsl/Cargo.toml
python analysis/prepare_web_shaders.py --dxc PATH/TO/dxc --spv2wgsl tools/spv2wgsl/target/release/spv2wgsl
```

Use `.exe` tool suffixes on Windows. Shader preparation needs DXC with SPIR-V
support. `analysis/extract_assets.py` additionally extracts DXBC/XM and uses
Windows D3DCompiler for reflection; Ghidra exporter scripts are in
`tools/ghidra/`. Normal player builds do not require these analysis tools.
